### 为什么做

### 用法
- `python3 00_系统/agent/wxmp-verify.py`（默认 /tmp/wxmp/articles.json，>2026-05-15）
- `--since YYYY-MM-DD` 改起始日期；`--fast` 跳过滚动（快，可能漏懒加载图）
- 逐篇比对线上真实 DOM 图 vs 归档 MD 图，输出类型（贴图/文章）、文件名是否匹配、源端漏收、MD 多出

### 写进脚本的 6 条踩坑
1. img_swiper 在 js_content 之外，必须单独取
2. **别只信 DOM**：等渲染时机不稳，连跑两轮同一篇能在 0/1 张之间跳 → 加原始 HTML
   正则扫 swiper_item 窗口兜底（data-src 是服务端渲染的，与渲染时机无关）
3. 按 mmbiz 图片 ID 去重（? 之前的路径）；同一张图有 tp=webp / from=appmsg / sz_mmbiz 变体
4. 排除 pic_blank.gif（1x1 空白间距）、video_player_tmpl（视频占位）、二维码
5. **内容类型看「有无」而非「等于几」**：贴图类页面才有 window.item_show_type='8'，
   文章类完全不出这个变量（页面里的 0/5 是 JS 常量表或比较语句）。
   第一版按值匹配，17 篇里 11 篇文章类全部取不到类型
6. **只算「源 − MD」会假绿**：源被频控抽空时差集为空，照样显示 0 缺失 → 改双向算，
   加降级页检测（环境异常/去验证等）+ 指数退避重试 3 次

### 真正根因
- 微信"图片轮播"组件 `#img_swiper`（`share_media_swiper`，Vue 渲染）承载正文图片，**位置在 `#js_content` 之外**（3.68MB 页面里位于 1,354,775 处，`#js_content` 在 1,363,389）

- 转换器只取 `#js_content` → 整块漏掉
- 另注：lxml 解析会截断该组件的 Vue 树（原始 36 处 `swiper_item`，解析后只剩 1 个），故用正则从原始 HTML 提
