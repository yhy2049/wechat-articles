# 群聊预筛选规则

> 管线 v0.4 试运行配套。群聊巡检采集的消息先过预筛选,再进 Quantize。

## 目标

过滤日常闲聊和纯状态消息,只保留可能包含可沉淀知识的消息,降低 Quantize 阶段的噪声。

## 筛选规则

### 通过(进入 Quantize)

消息满足以下任一条件即通过:

1. **包含决策**:出现了"决定"、"确认"、"改为"、"不再"、"以后"等决策关键词
2. **包含外部信息**:提到了具体公众号名、人名、日期、数字、外部链接
3. **包含问题或建议**:以问句形式出现,或包含"建议"、"应该"、"需要"等词
4. **包含行动项**:出现了"做"、"改"、"写"、"建"、"删"等动作词 + 具体对象
5. **来自审查/讨论环节**:小花/ming/毛毛在审阅文档、讨论方案时的实质性发言

### 拦截(不进入 Quantize)

消息满足以下任一条件即拦截:

1. **纯状态词**:仅包含“ok”、“收到”(无后续内容)、“好”、“嗯”、“继续”、“行”、“可以”、“没问题”等单字/词回复
2. **纯社交**:问候、闲聊、表情、无实质内容的寒暄
3. **工具调用反馈**:仅包含工具执行结果的格式化输出,无额外判断
4. **重复确认**:和上一条消息内容高度重复的确认/追问
5. **纯@提及**:仅包含“@某人”,无后续问题或内容

### 边界案例

- "收到,我去看一下" → 通过(包含行动项"看")
- "ok" → 拦截(纯状态词)
- "这个方案可以" → 通过(包含决策)
- "@小花 你看看" → 通过(包含行动项)
- "哈哈" → 拦截(纯社交)

## 实现方式

### v0.4 试运行(手动)

人工筛选。每次群聊会话结束后,由执行 agent 扫一遍消息,按上述规则过滤,只把通过的消息写入 `24帧运营库/00_系统/巡检日志/YYYY-MM-DD.md`。

### v1.0(自动)

用关键词匹配 + 简单规则引擎实现自动筛选。规则引擎的阈值根据 v0.4 试运行的信噪比数据调整。

## 信噪比目标

- 试运行期间:通过率 ≤ 30%(即70%以上的消息被过滤)
- 如果通过率 > 50%:规则太松,需要收紧
- 如果通过率 < 10%:规则太紧,可能漏掉有价值的消息
