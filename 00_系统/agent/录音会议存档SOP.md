# 录音/会议存档 SOP

> 适用场景：收到通话录音、会议转写、访谈记录等需要归档的原始材料时。
> 核心原则：**归档完成 = 存好的东西可以直接用**，不是"文件存好了"。

---

## 一、六步一次性完成（不分批、不等催）

### Step 1：转录存档
- 读取原始文件（.docx/.m4a 等）
- 清理噪音：删除转写软件的错标（如"1号讲话人"等未识别说话人）
- 统一格式：说话人名称 + 时间戳 + 内容
- 存入项目目录 `02_归档文件/`

### Step 2：信息提炼
从转录中提取并创建：
- **人物文件**（`03_人物/`）：新出现的人，记录身份、关系、行为记录、待观察
- **项目文件**（`02_项目/项目名/项目名.md`）：新项目的关键参数、双方分工、费用、时间线
- **任务文件**（并入 `02_项目/项目名/`，type: task）：待办事项，按时间线拆分（立即/短期/活动前）

### Step 3：背景调研
- 涉及的电影/项目/品牌 → 搜索背景信息，写入 `01_参考文档/电影背景.md`
- 涉及的人物 → 搜索公开信息补充画像
- 涉及的行业/市场 → 补充风险提示和市场判断

### Step 4：可交付物准备
根据内容类型准备对应材料：
- **通话录音** → 群聊对齐信息（整理好可直接发群的文字）+ 合作协议（完整版，非草稿）
- **内部会议** → 会议纪要（决策/待办/责任人）+ 项目/任务更新
- **观影团/活动** → 执行方案 + 招募文案 + 物料清单

所有可交付物必须达到"确认后可直接使用"的标准，不出草稿。

### Step 5：自我审计
对照前四项逐项打勾：
- [ ] 转录已存档且清理完成
- [ ] 人物/项目/任务文件已创建
- [ ] 背景调研已完成并写入参考文档
- [ ] 可交付物已准备且可直接使用
- **缺任何一项 = 归档未完成，不得汇报**

### Step 6：通知到位
- 在频道告知归档完成
- 附上提炼摘要（关键信息、创建了哪些文件、可交付物清单）
- 不只是"存好了"三个字，要说清楚做了什么

---

## 二、不同类型录音的侧重

| 类型 | 侧重 |
|------|------|
| 外部通话（合作方/客户） | 群聊对齐信息 + 协议 + 人物建档 + 项目建模 |
| 内部会议 | 会议纪要 + 决策记录 + 任务更新 + 关联项目/人物更新 |
| 观影团/活动复盘 | 执行总结 + 数据汇总 + 改进建议 + 任务闭环 |

---

## 三、质量标准

- **信息完整度**：关键参数（金额、时间、人数、分工）不能遗漏
- **可交付物标准**：确认后可直接使用，不是"还需要再改改"
- **背景调研深度**：涉及的电影/人物/品牌必须查，不能只搬运转录内容
- **时效性**：一次性完成，不分多个回合

---

## 四、常见陷阱

1. ❌ "归档 = 存文件" → ✅ "归档 = 存文件 + 提炼 + 调研 + 交付物 + 审计 + 通知"
2. ❌ "草稿先出了再说" → ✅ "出完整版，确认后直接用"
3. ❌ "等用户来问再做" → ✅ "一次性全做完，主动汇报"
4. ❌ "背景调研以后再补" → ✅ "归档时就查好，写入参考文档"
5. ❌ "只在自己session里处理" → ✅ "在频道里说清楚做了什么、怎么想的"
