# 经验沉淀

> agent 工作记忆，所有周期产出（lint / 灵感回看 / 复盘）的提炼终点。原始报告提炼到这里后即删。
> 每次跑 lint 前先读这页，让历史经验改变这一次的行动。这是 [[运营手册]] §13 复利的落地。

## 沉淀机制：产出 → 提炼 → 沉淀 → 调用

每产出一份报告，走"提炼三问"，不留报告全文：

1. 这次发现的是哪一类问题？压缩成一句，不记"这步怎么做"的细节。
2. 怎么防它再犯？给一个 action（改规则 / 改流程 / 加检查项）。
3. 这类问题出现过几次？反复出现（≥3 次）升级成手册里的硬规则。

三个去向：

- 一次性事实（这次修了什么）→ `_changelog` 已记，不另存。
- 可复用经验（这类问题怎么防）→ 记到下方。
- 反复出现的 → 升级进手册（§8 lint 项 / §15 入库清单），并在这里标"已升级"。

原始报告提炼完即删，自动汇总只留最近一份当健康快照。

## 已沉淀的经验

### 库维护类
- direction / status / progress 常被写成非枚举值（影视发行、active、筹备）。**已升级**：§4 列明枚举 + §15 入库自检。
- 新笔记常漏双链、漏 changelog。**已升级**：§15 入库检查清单设为硬线。
- 项目内预建空子目录。**已升级**：§10 子目录按需建。

### 协作类（提炼自三人复盘）
- 串行接力让执行和反对进场太晚。**已升级**：§6 执行预检 + 反对机制前移到方案阶段。
- agent 爱写一堆没有 action 的 lessons learned。**已升级**：§13 action 硬规则。

> 现有报告的精华大多已经升级进手册，这说明机制在转，原始报告可放心删。新发现按上面三问继续往下加。
