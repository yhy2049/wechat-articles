# 归档操作规范

> 24帧运营库的归档工作 SOP。Hermes 通过 `vault-archiving` skill 强制触发。
> 其他 agent 直接读本文件执行。
> 核心原则：**归档完成 = 存好的东西可以直接用**，不是"文件存好了"。

## 0. 前置检查

收到归档请求时，先确认：
1. 原始文件路径
2. 文件类型（.docx/.m4a/.txt/.pdf 等）
3. 涉及的项目/人物是否已有文件

---

## §15 归档专用子集（开工第一时间打开，按单施工）

开工前先走一遍这张清单，按照条款创建文件，边做边勾。不是做完再回头查。

### 开工前（2条）

- [ ] `ls` 目标目录，确认无重名、命名风格一致
- [ ] 新文件来自 markitdown 转换的，先清理残留：`sed -i '' '/^## Reader Warnings$/,/^## /{/^## /!d}' <file>`

### 写入时（2条）

**① frontmatter 按类型填**

| 文件类型 | 分类 | 必填字段（含通用字段） |
|---------|------|---------------------|
| 转录存档 | 原始笔记 | type: meeting, name, direction(方向名), project(项目名), status: archive, editable: false, audience, created, updated |
| 人物文件 | 衍生笔记 | type: person, name, status, editable, audience, created, updated |
| 项目 README | 衍生笔记 | type: project, name, status, priority, audience, created, updated |
| 任务文件 | 衍生笔记 | type: task, name, status, priority, assignee, due, audience, created, updated |
| 参考文档 | 可交付物 | type: reference, name, status, audience, created, updated |

通用字段：status, editable, audience, created, updated 全部文件必填。
AI 生成内容补 `source: ai-generated`。

**② 双链分两类走**

- **原始笔记**（转录存档）：不加出站双链。frontmatter 中 direction/project 必填，供其他笔记反向索引。
- **衍生笔记**（人物/项目/任务）：① 链到所属方向 `direction` 和项目 `project`；② 提到的人物、项目、其他笔记一律用 `[[wikilink]]`，不留纯文本。

### 收工后（3条）

- [ ] 记 `_changelog`：`## [YYYY-MM-DD HH:mm] 操作类型 | 文件名`
- [ ] 自检一句：有没有"该链却没链"的地方
- [ ] 会议存档专属：① 更新参会人物文件（行为记录、画像速写）② 同步项目和方向（新建项目 / 更新项目决策记录）。普通笔记入库跳过此条

## 六步流程（一次性完成，不分批，不等催）

六步流程在 §15 子集的框架下执行 —— 每步创建文件时，按 §15 要求写 frontmatter 和双链。

### Step 1：转录存档

1. 读取原始文件
2. 清理噪音：删除转写软件的错标（如"1号讲话人"等未识别说话人）
3. 统一格式：说话人名称 + 时间戳 + 内容
4. 存入项目目录 `02_归档文件/`（如项目目录不存在则先创建）
5. 写 frontmatter：type=meeting, direction, project, status=archive, editable=false 等
6. 不加出站双链

### Step 2：信息提炼

从转录中提取并创建：

**人物文件**（`04_人物/`）：
- 新出现的人，创建人物文件
- 包含：身份、关系、行为记录、待观察
- 检查是否已有同名文件，避免重复
- 用 `[[wikilink]]` 链回转录存档

**项目文件**（`02_项目/项目名.md`）：
- 新项目的关键参数、双方分工、费用、时间线
- 如项目目录不存在则创建
- 用 `[[wikilink]]` 链转录存档、人物文件

**任务文件**（任务并入项目，放 `02_项目/项目名/` 内，type: task）：
- 待办事项，按时间线拆分（立即/短期/活动前）
- 每个待办有明确的执行人和截止时间
- 用 `[[wikilink]]` 链项目文件

### Step 3：背景调研

- 涉及的电影/项目/品牌 → 搜索背景信息，写入 `01_参考文档/`
- 涉及的人物 → 搜索公开信息补充画像
- 涉及的行业/市场 → 补充风险提示和市场判断
- **不能只搬运转录内容，必须主动搜索补充**

### Step 4：可交付物准备

根据内容类型准备对应材料：

| 录音类型 | 可交付物 |
|---------|---------|
| 外部通话（合作方/客户） | 群聊对齐信息（可直接发群）+ 合作协议（完整版，非草稿） |
| 内部会议 | 会议纪要（决策/待办/责任人）+ 项目/任务更新 |
| 观影团/活动 | 执行方案 + 招募文案 + 物料清单 |

**质量标准：确认后可直接使用，不出草稿。**

### Step 5：自查与收工

对照 §15 收工后的 3 条逐项验证：
- [ ] `_changelog` 已记
- [ ] 没有"该链却没链"的地方
- [ ] 会议存档则更新了人物文件和项目方向

**缺任何一项 = 归档未完成，不得汇报。**

### Step 6：通知到位

在频道告知归档完成，附上提炼摘要：
- 创建了哪些文件
- 关键信息摘要
- 可交付物清单
- **不只是"存好了"三个字**

## 常见陷阱

1. ❌ "归档 = 存文件" → ✅ "归档 = 存文件 + 提炼 + 调研 + 交付物 + 审计 + 通知"
2. ❌ "草稿先出了再说" → ✅ "出完整版，确认后直接用"
3. ❌ "等用户来问再做" → ✅ "一次性全做完，主动汇报"
4. ❌ "背景调研以后再补" → ✅ "归档时就查好，写入参考文档"
5. ❌ "只在自己session里处理" → ✅ "在频道里说清楚做了什么"

```
24帧运营库/
├── 02_项目/
│   └── [项目名]/
│       ├── 项目名.md          # 项目概况（衍生笔记，链原始存档）
│       ├── 01_参考文档/       # 背景调研、协议、群聊信息
│       └── 02_归档文件/       # 原始转录存档（原始笔记，不加出站双链）
│       └── （任务文件放项目目录内，type: task，链项目）
├── 03_人物/
│   └── [人名].md             # 人物文件（衍生笔记，链原始存档）
```
