# 24帧运营库 · 运营手册

> 单一事实源。本手册合并了原 `_schema`、`工作指南`、`协作机制规则`、`方向归属决策规则` 四份文件，去掉重复，统一口径。
> 段落标签：【共读】人机都看 ·【AI】给 agent ·【人】给宇航员。
> 配套：操作日志 `_changelog.md`、内容索引 `_index.md`、会议/录音归档细节 `归档操作规范.md`。

## 设计哲学（共读，先读这段）

这个库是一个 AI 维护的运营管理库，骨架揉合了四套成熟方法，一句话概括：**人定方向给反馈，AI 把原始素材编译成结构化、强互链的库，每天从一个"现在"页看全局。**

四条核心原则：

1. **PARA 分层**（东西放哪）：内容分四类，各司其职。领域 = `01_方向`（持续在做的事，5 个活跃方向）；项目 = `02_项目`（有头有尾的事，任务并入项目，不设独立任务目录）；资源 = `03_人物` / `04_灵感`（参考素材）；归档与系统 = `05_档案`（含会议存档 / 公众号存档 / 媒体） / `00_系统`。方向是 Areas、项目是 Projects，本就分开，靠 `direction` 字段关联，不做物理嵌套。

2. **三个入口各管一摊**（从哪看）：`HOME` 是每天的"现在"，一眼看项目进度和待办，给宇航员；`_index` 是全库结构索引，给查找和 agent；`运营手册` 是规范与 agent 行为，单一事实源。（借鉴 second-brain 的 NOW / VAULT / AGENTS 三件套。）

3. **AI 编译，不只是存**（怎么长大）：原始素材（会议、对话）进来，AI 做书面化、提炼灵感、更新项目、建双链，把"原始"编译成"结构化"。全程 markdown、强 `**双链**`、AI 维护、人验收。这是 Karpathy LLM Wiki 的内核。

4. **少而清，宁删勿堆**（不失控）：顶层尽量少（参照 Johnny Decimal，越少越好找）；规则单一事实源不重复；经验压缩成一句话加一个 action，不堆长报告。

角色：宇航员是董事长，定方向、给反馈、拍红灯；agent 是执行，绿灯黄灯自主推进。AI 向宇航员的标准对齐，差异化在于"你"。

## 0. 怎么用（共读）

- **不读不动（硬规则）**：收到任何带名称的动作指令（归档、发布、迁移、清理等），执行前第一步必须打开对应的规范文件逐项对照。不跳过、不靠记忆、不凭经验。没读规范文件就开始执行 = 违规。
- **做完自查（硬规则）**：存档类操作（归档、写入、迁移等）执行完成后，执行人必须对照 `归档操作规范.md` 的检查清单逐项打勾，确认每一项都有对应产出物再标记完成。自查不过关不得视为完成。
- 每次动手前，先读本手册 + `_index.md`，了解现状再动。
- 每次动手后，在 `_changelog.md` 追加一条：`## [YYYY-MM-DD HH:mm] 操作类型 | 文件名`。
- 库结构有改动（新建目录、迁移文件、新增内容类型），先过三步：① 更新本手册的目录树；② 在新内容里标权限边界；③ 涉及新流程就同步到本手册。

### 1.1 会议文件唯一归属（硬规则）

所有会议、通话、访谈、录音转写，唯一存放位置是 `05_档案/会议存档/`，命名 `YYYY-MM-DD_主题.md`。

- 项目目录内（含 `02_归档文件/`）不存放会议记录；`02_归档文件/` 只放剧本、排期等项目原始素材。
- 项目与会议靠双链关联：项目页正文用 `[[会议文件名]]` 引用，会议页 frontmatter 用 `related_projects` 反向标注。
- 会议标准 frontmatter：`type: meeting, title, date, participants, direction, related_projects, related_people, tags, status: archive, editable: false, audience, created, updated, source`。

> 历史背景：早期 SOP 曾要求会议存入项目 `02_归档文件/`，与本规则冲突，已于 2026-06-19 统一废止，一律以本条为准。

### 权限边界

| 文件夹 | 权限 | 说明 |
| --- | --- | --- |
| 01_方向 | 可写 | 重大方向调整先问宇航员 |
| 02_项目 | 可写 | 每项目一文件夹，内按 01~04 子目录组织；会议不放这里 |
| 03_人物 | 可写 | 可创建 / 更新 |
| 04_灵感 | 可写 | 灵感 + 知识库 + 品牌策略，AI 自由加工 |
| 05_档案 | 只读 | 会议存档 + 公众号 + 媒体；仅宇航员可改，唯一例外是 agent 按归档 SOP 写入 `会议存档/` |
| 00_系统 | 受控 | 手册 / 索引 / 日志，按 §0 规则更新 |
