# 2026 多 Agent 架构模式全景

> 自主学习成果。梳理截至 2026 年 Q2 的多 Agent 架构模式分类、选择路径和框架支持。
> 来源：Digital Applied 2026 Taxonomy、Google ADK 8 Patterns、LangChain 4 Patterns、Openlayer Guide。

---

## 核心共识

多 Agent 架构知识体系在 2024-2026 年间趋于稳定，形成八种规范模式（覆盖四象限）。生产级系统通常是其中 2-3 种的组合。

**最关键的决策原则**：先单 Agent，再升级。绝大多数团队在单 Agent 质量尚未触顶时就不必要地引入了协调开销。

---

## Quadrant 1：单 Agent 模式

| 模式 | 原理 | 适用场景 | 失败模式 |
|------|------|----------|----------|
| **ReAct** | 交替推理+行动循环，每步观察更新下一步推理 | 通用 Agent 任务，<30 步 | 长程一致性丢失（>50步）；重复错误 |
| **Reflexion** | ReAct + 每步自批评，将批评追加到上下文 | ReAct 出现重复错误时；编程/数学 | 延迟增加 ~30%；过度修正导致振荡 |

> **生产级推荐栈**：ReAct + Reflexion。若规划是瓶颈加 plan-and-execute，若输出质量是瓶颈加 verifier-critic。

---

## Quadrant 2：协作式多 Agent

| 模式 | 原理 | 适用场景 | 失败模式 |
|------|------|----------|----------|
| **Plan-and-Execute** | Planner 输出计划 → Executor 逐步执行 | 可预测的已知结构流程 | 计划脆弱（环境变化时断裂）；能力不匹配 |
| **Supervisor-Worker** | 监督者分解任务 → 路由给专业 Worker，聚合结果 | 可分解为清晰子任务的工作；需 Worker 专业化 | 协调开销大于收益；监督者漂移；Worker 冲突未上报 |

> **生产级判断**：Hierarchical 几乎每次都能胜过 Swarm。监督者锚定目标对齐；Swarm 没有监督者容易飘移。

---

## Quadrant 3：竞争/对抗式多 Agent

| 模式 | 原理 | 适用场景 | 失败模式 |
|------|------|----------|----------|
| **多 Agent 辩论** | 多个 Agent 论证不同立场 → 独立判断者总结 | 高风险决策；安全性评估；发散式头脑风暴 | 过早收敛；辩论过长语言能力衰减；裁判偏长文本 |
| **Verifier-Critic** | 生成 → 评判（按评分标准）→ 修订→ 循环 | 高精度输出；安全过滤；内容质量把关 | 同模型评判-生成合谋；过度修正边缘案例 |

---

## Quadrant 4：编排拓扑模式

| 模式 | 原理 | 适用场景 | 失败模式 |
|------|------|----------|----------|
| **Graph 编排** | Agent 作为有向图节点，显式边控制流 | 结构化工作流；需 trace 级调试的系统 | 图复杂度增长快；未覆盖的边界条件 |
| **Swarm/Blackboard** | 对等拓扑，无监督者，通过共享黑板/消息总线 | 探索型任务（分解方式不明确时）；研究/头脑风暴 | 目标漂移；协调死锁；调试困难 |

> **生产级推荐**：Graph > Hierarchy > Swarm。Graph 和 Hierarchy 在 95% 的用例中值得付出开销。

## Google ADK 的 8 种模式

补充视角，面向 ADK 的实现层面的模式划分：

1. **Sequential Pipeline** — 流水线式链式传递，确定性、易调试
2. **Coordinator/Dispatcher** — 中央决策者路由到专业 Agent
3. **Parallel Fan-Out/Gather** — 并行执行 → 综合 Agent 聚合
4. **Hierarchical Decomposition** — 高层 Agent 分解任务，委托给子 Agent
5. **Generator and Critic** — 生成+校验条件循环
6. **Iterative Refinement** — Generator → Critique + Refiner 迭代改进
7. **Human-in-the-Loop** — 审批工具 Agent 在关键节点暂停，等待人工确认
8. **Composite** — 以上模式任意组合

## LangChain 的 4 种模式

另一种视角，面向应用开发的模式划分：

| 模式 | 原理 | 最佳场景 | 关键权衡 |
|------|------|----------|----------|
| **Subagents** | Supervisor 将子 Agent 当工具调用 | 多领域协调、并行 | +1 模型调用/轮的延迟开销 |
| **Skills** | 按需加载专业提示和知识（准多 Agent） | 单 Agent 多元专长 | 上下文不断累积，token 膨胀 |
| **Handoffs** | 基于对话上下文动态切换活跃 Agent | 客服分流、多阶段对话 | 需要精细状态管理 |
| **Router** | 路由分类 → 并行派发 + 综合 | 独立垂直领域查询 | 无状态 → 需额外维护对话历史 |

## 模式选择决策树

```
Step 1: 从 ReAct 基线开始 → 测成功率/准确率/延迟/成本
Step 2: 如果失败重复出现 → 加 Reflexion（质量提升 10-30%，延迟 +30%）
Step 3: 如果循环 >30 步 → 加 re-anchor 检查点
Step 4: 高风险的输出质量要求 → 加 Verifier-Critic
Step 5: 以上都无法突破 → 评估升级到多 Agent
         - 任务可分解为清晰子任务？→ Supervisor-Worker
         - 需要结构化流程？→ Graph 编排
         - 探索型/不确定分解方式？→ Swarm（只选这个）
```

## 2026 新趋势

- **Anthropic 研究**：多层多 Agent（Claude Opus 4 作为 Lead + Sonnet 4 Subagents）在内部研究评估中比单 Agent Opus 4 高出 **90.2%**
- **角色拆分**：给 Agent 分配明确身份（Parser/Critic/Dispatcher），实现"AI 的微服务架构"
- **事件驱动**：借鉴微服务的事件驱动模式应用于多 Agent 系统，解决协调混乱问题
- **MCP 协议 + 技能系统**：工具和技能的标准化接口成为多 Agent 编排的新基础设施层
