# Agent 记忆系统 2026：生产生态调研

> 自主学习笔记 2026-06-06
> 基于 Mem0《State of AI Agent Memory 2026》等行业报告，补充《分层架构推演》笔记中的"理论 vs 现实"映射

---

## 一、为什么这篇笔记值得看

之前的《分层架构推演》从原理出发，推导了 Agent 知识内化的三层结构（热/温/深）。这篇反过来——从 2026 年上半年的实际生产生态出发，看行业在做什么、遇到什么瓶颈、哪些方向已经被验证，与理论框架对照验证。

---

## 二、记忆层不再是"可选组件"

2024 年以前的 Agent 记忆 ≈ 把对话历史塞进 context window。2026 年，记忆被正式确立为**第一等架构组件**：

- 有独立的评测基准（LoCoMo / LongMemEval / BEAM）
- 有专门的研究论文（ECAI 2025 的 Mem0 论文做了最早的 10 种方案对比）
- 有可量化的性能差距（好的记忆系统在时序推理上高出基准 29.6 分）
- 生态整合涵盖 21 个框架 + 20 种向量存储后端

这与《分层架构推演》的判断一致：Memory 不是 RAG 的子集，是一个独立的架构层。

---

## 三、三个关键评测基准

| 基准 | 规模 | 测试维度 | 意义 |
|------|------|---------|------|
| **LoCoMo** | 1,540 题 | 单跳/多跳/开放域/时序记忆 | 第一个可复现的记忆对比基准 |
| **LongMemEval** | 500 题 | 6 类场景含知识更新/多会话 | 对知识更新和跨会话任务要求极高 |
| **BEAM** | 1M~10M token | 10 类含偏好遵循/矛盾消解 | 测试大上下文下的真实生产能力 |

**关键洞察**：BEAM 无法通过简单扩展 context window 解决。这意味着"窗口再大也不行"——存和取是两个不同的问题。

---

## 四、从记忆到"内化"：架构演进

### 4.1 RAG ≠ 记忆（一个被混淆了很久的区别）

来自 XTrace 的一段精辟对比：

> **RAG** 适合读图书馆，但写不了自传。
> **Agentic Memory** 是一个读写系统，跟踪用户/工作流的**演化状态**：偏好、决策、纠错、历史。
> RAG 基于相似度检索，不更新状态，没有时间感。

这与《分层架构推演》中"热知识 vs 温知识 vs 深知识"的划分高度吻合。RAG 适合 L1（热知识），对 L2（温知识）是辅助，对 L3（深知识）无能为力。

### 4.2 2026 年最值得关注的架构改进

**方向一：多信号融合检索**

不再是单一向量相似度。2026 年的 State-of-the-Art 方案同时跑三路评分：
1. **语义相似度**（向量嵌入）
2. **BM25 关键词匹配**（精确匹配）
3. **实体匹配**（命名实体对齐）

三路归一化融合后排序。最大提升在时序推理（+29.6 分）和多跳推理（+23.1 分）——恰是真实用户场景中最关键的维度。

**方向二：记忆的参与者感知**

多 Agent 协作中，一条记忆"用户需要部署帮助"——但这是用户自己说的，还是监控 Agent 推断的，还是规划 Agent 创建的中间步骤？三者性质完全不同。

2026 年的方案用消息 `name` 字段归因：用户消息记 `user_id`，助手/Agent 消息记 `agent_id`。检索时可按参与者和会话过滤，分离用户陈述事实与 Agent 生成推断。这解决了一个实际的信任问题。

**方向三：四层作用域模型**

每条记忆关联最少一个作用域：
- `user_id`：跨会话的个人记忆
- `agent_id`：特定 Agent 实例的记忆
- `run_id/session_id`：单次对话的工作记忆
- `app_id/org_id`：组织级共享知识

作用域可组合。查询时自动合并排序（用户记忆 > 会话上下文 > 原始历史）。

**这四层直接对应《分层架构推演》的 L1（run_id）和 L2（user_id/agent_id）。**

### 4.3 图记忆的定位变化

2024 年图记忆是热点，2026 年生产模式的结论是：
> 不是"每个 Agent 都需要图数据库"，而是记忆系统需要超越纯向量相似度。

当前的做法是用**内置实体链接**（add 时抽取实体，搜索时匹配提升），放弃可遍历的图接口，换取零额外部署成本。这是一种务实权衡：对需要自定义推理的团队是退步，对大多数需要实体感知检索的团队是净收益。

## 五、多 Agent 框架生态：2026 格局

| 框架 | 定位 | 记忆方案 | 适合场景 |
|------|------|---------|---------|
| **LangGraph** | 状态化 Agent 工作流 | Checkpointer + Store API 原生持久化 | 复杂多步骤流程 |
| **CrewAI** | 多 Agent 团队协作 | 集成 Mem0 等外部记忆 | 角色分工明确的团队 |
| **OpenAI Agents SDK** | 轻量 Agent 构建 | 手写记忆逻辑或接入外部 | 快速原型 |
| **Google ADK** | 多 Agent 层级 | 原生支持 A2A 协议 | 跨框架协作 |
| **Claude Agent SDK** | Anthropic 生态 | 内置记忆 | 基于 Claude 的应用 |

**趋势**：2026 年没有单一框架胜出，开发者跨框架构建。记忆层锁定单一框架即锁定市场，所以主流记忆系统（如 Mem0）做的是框架无关的整合层。

## 六、开放问题（与推演笔记交叉验证）

《分层架构推演》提出的 4 个开放问题，在 2026 年行业实践中得到的回答：

| 问题 | 行业状态 |
|------|---------|
| **内化的度量** | 已有 LoCoMo/LongMemEval/BEAM 三套基准，但都偏"记忆召回"而非"内化深度" |
| **遗忘曲线** | 成熟方案提供 TTL 和优先级衰减，但"合理阈值"仍靠调参，无理论共识 |
| **跨 Agent 知识共享** | 多作用域模型（user/agent/org）是当前方案，但"知识迁移"的问题未解决 |
| **内化 vs 外挂的边界** | 共识是：高频/稳定→内化，低频/动态→外挂，但"边界线在哪"无定论 |

## 七、对当前 HanaAgent 系统的映射

结合团队已有的实践（置顶记忆、经验库、技能），行业趋势指向几个可尝试的方向：

1. **检索信号多样化**：目前经验库只有语义匹配，可增加关键词+实体匹配辅助，提升命中率
2. **记忆的参与者和作用域**：多 Agent 场景下，一条经验是谁产生的、适用于谁，需要记录
3. **自动反馈闭环**：经验被调用后，执行结果能否自动修正该经验的权重/内容
