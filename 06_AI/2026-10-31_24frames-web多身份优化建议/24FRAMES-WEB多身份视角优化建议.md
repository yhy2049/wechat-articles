## 一、身份 A · 购买者（观众 / 影迷）

**目标**：3 步内买上票 → 到现场出示二维码进场；退票/转让不折腾。

**关键旅程**：微信群/公众号推文 → 活动详情 → 选座 → 填信息 → 支付 → 电子票 → 到场核销。

**现状观察（实测）**：
- 详情页信息全（时间/影院/影厅/票价/余票/日程/周边/须知），选座有最佳区、无障碍座、锁座 10 分钟倒计时；购票人信息本地自动填充；手机号校验；电子票含二维码/订单号/ICS 日历/打印/转让；PWA 断网可看票。
- **痛点**：
  1. 支付是**模拟**——观众以为付了钱，实际没扣款（信任 + 无法真运营）。
  2. **无账号**——换手机/清缓存，票夹 0 张，票没了；现场找不到票很慌。
  3. **无通知**——买完票不知道是否改期/取消；候补递补没提醒；退款到账没提示。
  4. **选座草稿不跨刷新**——刷新支付页丢选座，得重选（当前仅会话内保留）。
  5. 微信内打开是 hash 链接，摘要/卡片受限制（OG 已补，但抓取仍受限）。

**优化建议（按价值）**：
| # | 建议 | 为什么 |
| --- | --- | --- |
| A1 | 账号登录（手机号验证码或微信授权），票夹跟随账号 | 换设备票不丢；现场核销/改签有依据。P0 |
| A2 | 真实微信支付，支付成功才占座，失败不占座 | 解决「以为付了」的信任硬伤。P0 |
| A3 | 通知：购票成功/开场前一天/候补递补/退款到账 | 降低放鸽子 + 提升到场；候补/转让体验不断。P1 |
| A4 | 选座草稿写 sessionStorage（10 分钟恢复），刷新不丢 | 减少流失；配合服务端锁座更稳。P1 |
| A5 | 微信内分享卡：用 History 路由或预渲染出干净链接 + 清晰海报摘要 | 提高点击率与品牌专业感。P2 |
| A6 | 选座增强：2 人/3 人连座推荐、座位图缩放、最佳区切换 | 同行选座更顺。P2 |
| A7 | 到场入口：扫码核销提示更醒目（到场前把「出示二维码」做成常驻顶栏） | 现场减少卡顿。P2 |

## 二、身份 B · 合作方（影院 / 片方发行 / 品牌 / 媒体 / 高校）

**目标**：相信 24帧 是靠谱的放映伙伴 → 看到合作案例与效果 → 低成本建立联系。

**关键旅程**：被推荐/搜索到官网 → 看「关于」与「合作与包场」→ 评估专业度 → 联系洽谈。

**现状观察（实测）**：
- `#/about`：品牌主张 + 数据（300 场 / 10000 人次 / 50 部 / 302 篇）+ 五项实践 + 代表项目 + 2022–2026 时间线 + **合作与场地**（FIRST / 戛纳一日 / 海南电影节 / 非定 / 木圭 / 方所 / 麓湖 / MAO / 保利万和 / 四川传媒学院）+ **找到我们**（小助手微信 / 邮箱 / 商务微信 / 公众号小红书）。
- 页脚有「合作与包场」→ 跳到 `#/help` 的 FAQ「可以包场或合作吗？」→ 加小助手微信。
- **痛点**：
  1. **合作入口弱**——「合作与包场」落在帮助页 FAQ，不像商务入口；无联系方式表单，只能加微信。
  2. **缺合作效果数据**——有总量（300 场/万人次），但无「单场合作上座率、路演票房、口碑传播」这类片方/影院最想要的效果证明。
  3. **缺媒体/PR 资料包**——片方、媒体常要：活动高清照片、海报源文件、票房/到场数据、采访联系人；官网无资源区。
  4. **合作方品牌露出有限**——活动页有影院/影厅名，但无合作方 logo 墙或「联合呈现」区（片方、品牌）。
  5. 无「合作案例页」——不能按合作方类型（影院/片方/品牌/高校）筛选查看历史合作。

**优化建议（按价值）**：
| # | 建议 | 为什么 |
| --- | --- | --- |
| B1 | 独立「合作」页（非帮助 FAQ）：合作方式（路演/包场/联合策展/场地合作/媒体合作）+ 联系表单（单位/意向/联系方式） | 合作方最需要的是**正式入口**。P1 |
| B2 | 合作效果数据：每场路演的上座率、到场人次、映后反馈、媒体/社交传播量；按合作方汇总 | 片方/影院要**效果证明**。P1 |
| B3 | 媒体/PR 资料包：活动高清图、海报源文件、数据速览、采访联系人，可下载 | 媒体合作的基础物料。P2 |
| B4 | 合作方 logo 墙 / 「联合呈现」区：活动详情与关于页展示片方、品牌、场地标识 | 让合作方感到被尊重、有露出。P2 |
| B5 | 合作案例页：按影院 / 片方 / 品牌 / 高校分类的历史合作清单 | 建立信任背书。P2 |

## 三、身份 C · 后台运营者（24帧团队）

**目标**：高效建活动、管订单、核销、看数、防错、多人协作。

**关键旅程**：新建/复制活动 → 发报名 → 盯订单/候补/审核 → 现场核销 → 复盘数据。

**现状观察（实测）**：
- 后台：概览（票房/票数/订单/核销率/按场票房/最近订单/渠道与到场/候补转化）、放映活动（新建 5 段式：基本信息/时间场地/报名票务/报名表单/活动说明）、订单（筛选/CSV/批量审核/详情/补录/导入外部名单）、场地（影院→影厅）、核销（输入订单号/示例/最近核销）。
- 新建活动有「报名渠道：本站选座 / **外部报名工具**（适用于小萝卜等 H5）」+ 外部链接/文案；报名字段支持文本/手机/邮箱/多行/单选。
- 重置演示数据有确认弹窗（防误触，好）。
- **痛点**：
  1. **无登录**——任何人可进后台改活动、核销、导出订单（安全 + 无权限分级）。
  2. **localStorage 单机**——换电脑看不到订单；多人协作、线上多端不同步；这是运营最大硬伤。
  3. **模拟支付**——无法对账真金、无法退款到账管理。
  4. **核销靠输入**——现场扫码需摄像头识别（建议 `BarcodeDetector`/jsQR）+ 弱网离线名单。
  5. **无通知**——候补递补/退票/改期无法自动触达观众，只能手动。
  6. **建活动素材受限**——海报只能从内置素材选，不能上传；在线匹配已有但非全部片源有资料。
  7. **数据报表**——有渠道/到场/核销/候补转化，但缺「单场收支（含手续费）」与完整转化漏斗。
  8. **多管理员**——未实现（小萝卜有 add-admin）。
  9. **外部名单对账**——外部工具退款/改签不会自动回写，需手动对账（OPTIMIZATION 已注明）。

**优化建议（按价值）**：
| # | 建议 | 为什么 |
| --- | --- | --- |
| C1 | 服务端（Cloudflare D1 + Pages Function）：活动/订单/座位/核销入库，事务锁座 | 解决单机、并发、多人协作的**根**。P0 |
| C2 | 后台登录 + 角色（超管/核销员/编辑） | 安全 + 分工。P0 |
| C3 | 真实微信支付（回调后才占座；退款原路；重复回调防重） | 可对账、可运营。P0 |
| C4 | 核销扫码（摄像头）+ 当前场次名单离线缓存 | 现场效率 + 弱网兜底。P1 |
| C5 | 通知：候补递补/退票/改期自动提醒 | 减少现场空座。P1 |
| C6 | 海报/素材上传；单场收支与转化漏斗报表 | 建活动省事 + 决策有据。P2 |
| C7 | 多管理员（邀请协作）+ 操作日志 | 团队协作可追溯。P2 |

## 四、落地顺序建议（给运营者）

1. **先做共享地基**（三方都受益）：服务端数据 + 登录 + 真实支付（C1/C2/C3 与 A1/A2、B 无关，但它是 A1/A2 的前提）。这一步做完，站点才从「演示」变「可运营」。
2. **再做购买者体验**：账号票夹（A1）+ 通知（A3）+ 选座草稿恢复（A4）。
3. **同时补合作方入口**：独立合作页（B1）+ 合作效果数据（B2），成本低、对拉片方/影院帮助大。
4. **最后打磨**：核销扫码（C4）、媒体资料包（B3）、选座连座（A6）、多管理员（C7）。

> 一句话：**先把「地基」（服务端+登录+真支付）打好，三个身份的问题就解决了一大半；再用「合作页 + 通知 + 账号票夹」补齐合作方与购买者体验。**
